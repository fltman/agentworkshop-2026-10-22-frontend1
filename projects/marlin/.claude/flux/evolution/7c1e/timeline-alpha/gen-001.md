# Timeline-alpha, gen-001

## Approach

RAPTOR: round-based search. Round k contains all journeys using exactly k transit legs.
Per round, scan each route touched in the previous round once, and relax footpaths after.

## Why this approach could win

- max transfers = number of rounds, so the user setting is the loop bound, not a filter
- no priority queue, pure array scans, cache friendly
- naturally produces earliest arrival per stop, which is exactly what a band needs

## Risks

- needs routes grouped by stop sequence, which depends on vijay-team's shape
- max waiting time is not native to RAPTOR, has to be enforced when picking a trip
