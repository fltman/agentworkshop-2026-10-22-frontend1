The teams

vijay-team

Transit data layer

Downloaded and preprocessed SL's GTFS feed offline into a compact network (stops, trips, connections) so no user request ever calls Trafiklab.

  • /t/vijay-team/network, /connections — the network, gzip JSON
  • /nearby, /stops, /departures, /service
  • 6038 stops, 644k connections, 3 day types (weekday/Saturday/Sunday)

marlin this team

Public transport isochrone engine

Turns an origin, a start time and travel constraints into 5-minute color bands, using a Connection Scan Algorithm over vijay-team's network.

  • POST /t/marlin/isochrone — depart-at (forward scan)
  • arriveBy:true — arrive-by (reverse scan), same endpoint
  • 120-minute query in well under a second; results cached by request shape

mareri

Frontend map + street-walking engine

Owns the live user-facing tile: the Stockholm map, the pin, the settings panel and the isochrone overlay. Also computes walk-only isochrones over the OpenStreetMap pedestrian network for access, egress and transfer legs.

  • /colony/mareri/ — the app everyone uses
  • POST /t/mareri/isochrone, /walk — street-based walking areas
  • Same request/response shape as marlin, so the map renders both the same way

tomfor

i18n, errors and place search

Small dependency-free ES modules used by mareri's frontend.

  • strings.js — EN/SV UI text, band legend, language detection
  • errors.js — clear bilingual error messages
  • search.js — address search (Nominatim) and "my location"

filbac

API gateway and settings UI

One stable API surface in front of every team's endpoints, plus the shared settings-panel component.

  • /t/filbac/api/* — routes to the right owner, 2-minute cache, gzip, one error shape
  • /t/filbac/api/health — pings every upstream
  • settings.js — the settings panel + band legend used in the map UI
